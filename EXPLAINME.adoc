== Core Claims

=== Claim 1: Cross-Modal Constraint Convergence Recovers Damaged Data Through 5-Phase Constraint Propagation

*From README:* "A database recovery and reconstruction tool that uses VeriSimDB's octad model and VCL-total's progressive type system to reassemble damaged, fragmented, or inconsistent datasets through cross-modal constraint propagation... Data that passes all 10 levels is formally verified as recovered."

*Evidence:* The reconstruction engine at `src/engine/` is designed as 5-phase progressive constraint propagation: Phase 1 (Loose Constraints, VCL-total Levels 1-3) accepts anything structurally valid; Phase 2 (Cross-Modal Inference) uses populated modalities to infer missing ones (document text → graph edges via NER, graph edges → semantic annotations); Phase 3 (Conflict Resolution) arbitrates contradictions via provenance chains and temporal versions; Phase 4 (Tightening, VCL-total Levels 4-6) enforces null-safety and injection-proofing; Phase 5 (Convergence, VCL-total Levels 7-10) achieves cardinality bounds and linearity. `src/abi/mod.rs` states the invariants the engine must satisfy, in the form an honest mechanisation can target (lexicographic progress rather than monotone real-valued drift; identity preservation; purity of resolve; the VCL-UT ratchet; well-founded termination). **Caveat (2026-11-04):** this is concept stage. The engine, ingest and VeriSimDB client are stubs; no Idris2 proofs exist in this repository yet; VCL-UT can only certify levels L0–L6 from source today. The route to closing each of these gaps is `docs/ROUTE-PLAN.adoc`.

=== Claim 2: Eight Independent Representations (Octad Modalities) as Mutual Witnesses for Entity Identity

*From README:* "When you have 8 independent representations of the same entity, damage to any one can be compensated by the others... Eight witnesses are better than one."

*Evidence:* The design document in the README details the octad modality set: Document text (natural language), Graph edges (semantic relationships), Vector embeddings (latent space), Temporal history (version chains), Provenance metadata (hash chains), Spatial coordinates (geospatial data), Semantic types (formal schema), Tensor data (numerical arrays). The planned cross-modal inference transformations are: document text → graph edges via NER, document text → vector embedding via encoding, graph edges → semantic annotations via type inference, provenance → temporal ordering via hash-chain sequencing, spatial coords → graph proximity via spatial join, tensor data → vector projections via dimensionality reduction. When any modality is damaged or missing, others can reconstruct it. Drift is an observable, not the convergence measure: the measure is the pair (missing modalities, unresolved conflicts), which is what actually decreases. **Caveat:** none of these transformations exist in this repository yet; VeriSimDB ships only deterministic baselines (Graph→Document relation text, Document→Vector feature hashing). NER and real embeddings depend on external models.

== Dogfooded Across The Account

Squeakwell uses the hyperpolymath ABI/FFI standard (Idris2 ABI + Zig FFI). Same architecture pattern used across:
- https://github.com/hyperpolymath/proven[proven] (formal verification toolkit)
- https://github.com/hyperpolymath/burble[burble] (control plane with coprocessors)
- https://github.com/hyperpolymath/gossamer[gossamer] (window management system)
- https://github.com/hyperpolymath/idaptik[idaptik] (game engine)

Part of the -iser ecosystem for domain-specific query and recovery tools (TypedQLiser, Chapeliser, VeriSimiser, Squeakwell).
